
# OceanCloud Security Policy

## Our security commitment

Security is an important part of OceanCloud's development.

We take the protection of source code, accounts, infrastructure, user information and confidential project materials seriously.

## Reporting a security vulnerability

If you discover a potential security vulnerability affecting OceanCloud, please report it responsibly.

**Do not publish details of an unpatched vulnerability in a public issue, discussion or pull request.**

Preferred reporting method:

1. Check whether GitHub Private Vulnerability Reporting is enabled on this repository.
2. If enabled, use the repository's private security reporting feature.
3. If it is unavailable, contact OceanCloud project leadership through an appropriate private GitHub contact channel and request a secure reporting method.

Do not include passwords, access tokens, private keys or unnecessary personal information in a report.

## What to include in a report

Where possible, provide:

- A short description of the suspected vulnerability.
- The affected component or file.
- The potential security impact.
- Steps to reproduce the issue safely.
- Relevant logs or screenshots with secrets removed.
- Any suggested mitigation.

## Responsible testing

Security testing must only be conducted on systems for which you have explicit authorization.

Do not:

- Attack OceanCloud infrastructure without permission.
- Access another person's account or information.
- Extract, modify or destroy data.
- Conduct denial-of-service testing.
- Publish confidential vulnerability details without authorization.

## Security review

Reported vulnerabilities will be assessed and may be:

- Confirmed and assigned a severity.
- Investigated further.
- Fixed through a security update.
- Closed if they are not reproducible or are outside the project's scope.

## Disclosure

Please allow the project reasonable time to investigate and address a confirmed vulnerability before publicly disclosing technical details.

Any coordinated disclosure must be agreed with the affected parties.

## Contributor responsibilities

Contributors must:

- Protect credentials and secrets.
- Use approved development environments.
- Avoid committing `.env` files or private keys.
- Review dependencies and third-party licences.
- Report accidental exposure of confidential information promptly.

## Current project status

OceanCloud is under active development. This policy does not claim that all OceanCloud services are currently deployed, independently audited or production-ready.

Security is an ongoing engineering responsibility.
